# JHipster v9.4.0 リリース

これはJHipster v9のマイナーリリースです。

これは、[9.3.0 リリース](/2026/08/30/jhipster-release-9.3.0.html)以降、[272件のクローズされた課題とプルリクエスト](https://github.com/jhipster/generator-jhipster/issues?q=is:closed+milestone:9.4.0)を含んでいます。

大きなニュースはPlaywrightのサポートです！Cypressの代替としてPlaywrightでエンドツーエンドテストを生成できるようになり、仕様は行ごとに移植されているため、両者を比較できます。このリリースでは、webpackからの移行も完了しました。Angularマイクロフロントエンドは、esbuildベースのAngular CLIビルダーの上にNative Federationを使用するようになり、AngularおよびVueアプリからwebpackがなくなりました（[Reactは9.3.0でViteに切り替わりました](/2026/08/30/jhipster-release-9.3.0.html)）。

## 新機能

* [Playwrightがサポートされるe2eテストフレームワーク](https://github.com/jhipster/generator-jhipster/pull/34892)となり、Cypressと並んで選択可能になり、Angularアプリは`ng e2e`で実行できます。
* [Angularマイクロフロントエンドは、webpack Module Federationの代わりにesbuildとNative Federation](https://github.com/jhipster/generator-jhipster/pull/34672)で構築されるようになり、[Vue](https://github.com/jhipster/generator-jhipster/pull/34821)からもwebpackのサポートが削除されました。VueアプリはViteまたはRsbuildで構築されます。
* セキュリティ強化：[yeoman-generator v9](https://github.com/jhipster/generator-jhipster/pull/34919)は、テンプレートまたは出力パスがジェネレータのルート外に解決される場合にエラーをスローするようになり、[`--disable-blueprints`はローカルの`.blueprint`ディレクトリも無効にします](https://github.com/jhipster/generator-jhipster/pull/35008)。
* [R2DBCリポジトリは、jhipster-frameworkの[CriteriaBuilder](https://github.com/jhipster/generator-jhipster/pull/34822)を使用して、Criteriaを持つSpring Dataリポジトリの上に[再実装されました](https://github.com/jhipster/generator-jhipster/pull/34793)。
* [LiquibaseがCassandraをサポート](https://github.com/jhipster/generator-jhipster/pull/34724)し、デフォルトで有効になったため、スキーマはアプリケーション外の別のDockerイメージを必要としなくなりました。
* 新しい[`jhipster describe`コマンド](https://github.com/jhipster/generator-jhipster/pull/34864)は、コマンド、オプション、プロンプト、および設定所有者のクエリ可能なカタログを提供します。
* 新しい[`--export-application`オプション](https://github.com/jhipster/generator-jhipster/pull/34913)は、生成されたファイルをディスクに書き込む代わりにzipアーカイブにパックします。
* ブループリントの作成者は、[semver保証付きの文書化された公開API](https://github.com/jhipster/generator-jhipster/pull/34989)を利用できるようになりました。
* 多くの古い問題が修正されました。これには、[String IDを持つAngularエンティティ](https://github.com/jhipster/generator-jhipster/pull/34869)、[データベースなしのOAuth2ゲートウェイでのビルドエラー](https://github.com/jhipster/generator-jhipster/pull/34866)、[すべてのユーザーレコードを削除するテスト](https://github.com/jhipster/generator-jhipster/pull/34867)、および[MapStruct式フィールドの増分Liquibaseチェンジログ](https://github.com/jhipster/generator-jhipster/pull/34984)が含まれます。
* ビルドツールを[Node.js 24.21.0](https://github.com/jhipster/generator-jhipster/pull/34876)、[Cypress 16](https://github.com/jhipster/generator-jhipster/pull/34823)、および[Vitest 5](https://github.com/jhipster/generator-jhipster/pull/34852)にアップグレードしました。

## インストール方法

NPMを使用してJHipster v9.4.0をインストールするには：

```
npm install -g generator-jhipster@9.4.0
```

JHipster Dockerイメージを使用しても利用可能です。これはソースコードから自動的にビルドされます。

- [Docker Hub](https://hub.docker.com/r/jhipster/jhipster)
- [JHipster Online](https://start.jhipster.tech)

## アップグレード方法

**自動アップグレード**

自動アップグレードの場合、既存のアプリケーションで[JHipsterアップグレードサブジェネレータ](/upgrading-an-application/)を使用します：

JHipsterのバージョンをアップグレードします：

```
npm update -g generator-jhipster
```

そして、アップグレードサブジェネレータを実行します：

```
jhipster upgrade
```

より高度なアップグレード機能には、[migrateブループリント](https://github.com/jhipster/generator-jhipster-migrate)も使用できます。

```
npm i -g generator-jhipster-migrate
jhipster-migrate
```

**手動アップグレード**

手動アップグレードの場合、まずJHipsterのバージョンを次のようにアップグレードします：

```
npm update -g generator-jhipster
```

既存のプロジェクトがある場合、それは生成されたJHipsterのバージョンを使い続けます。
プロジェクトをアップグレードするには、まず`node_modules`フォルダを削除し、次に以下を実行する必要があります：

```
jhipster
```

プロジェクトとそのすべてのエンティティを更新するには、以下を実行することもできます：

```
jhipster --with-entities
```

エンティティサブジェネレータを再度実行することで、エンティティを1つずつ更新することもできます。例えば、エンティティ名が_Foo_の場合：

```
jhipster entity Foo --single-entity
```
