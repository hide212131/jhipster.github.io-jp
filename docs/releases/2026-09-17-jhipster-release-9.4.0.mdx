# JHipster リリース v9.4.0

これはJHipster v9のマイナーリリースです。

[9.3.0リリース](/2026/08/30/jhipster-release-9.3.0.html)以降、[272件のクローズされた課題とプルリクエスト](https://github.com/jhipster/generator-jhipster/issues?q=is:closed+milestone:9.4.0)が含まれています。

大きなニュースはPlaywrightのサポートです！Cypressの代替としてPlaywrightでエンドツーエンドテストを生成できるようになり、仕様は行ごとに移植されているため、両者を比較できます。このリリースでは、webpackからの移行も完了しました。Angularマイクロフロントエンドは、esbuildベースのAngular CLIビルダーの上にNative Federationを使用するようになり、AngularおよびVueアプリからwebpackがなくなりました（[Reactは9.3.0でViteに切り替わりました](/2026/08/30/jhipster-release-9.3.0.html)）。

## 新機能

* [Playwrightがサポートされるe2eテストフレームワークになりました](https://github.com/jhipster/generator-jhipster/pull/34892)。Cypressと並んで選択可能で、Angularアプリは`ng e2e`で実行できます。
* [Angularマイクロフロントエンドは、webpack Module Federationの代わりにesbuildとNative Federationで構築されるようになりました](https://github.com/jhipster/generator-jhipster/pull/34672)。[Vue](https://github.com/jhipster/generator-jhipster/pull/34821)からもwebpackのサポートが削除されました。VueアプリはViteまたはRsbuildでビルドされます。
* セキュリティ強化：[yeoman-generator v9](https://github.com/jhipster/generator-jhipster/pull/34919)は、テンプレートまたは出力パスがジェネレーターのルート外に解決される場合にエラーをスローするようになり、[`--disable-blueprints`はローカルの`.blueprint`ディレクトリも無効にします](https://github.com/jhipster/generator-jhipster/pull/35008)。
* [R2DBCリポジトリは、jhipster-frameworkのCriteriaBuilder](https://github.com/jhipster/generator-jhipster/pull/34822)を使用して、Criteriaを持つSpring Dataリポジトリの上に[再実装されました](https://github.com/jhipster/generator-jhipster/pull/34793)。
* [LiquibaseがCassandraをサポートするようになり](https://github.com/jhipster/generator-jhipster/pull/34724)、デフォルトで有効になりました。これにより、スキーマはアプリケーション外の個別のDockerイメージを必要としなくなりました。
* 新しい[`jhipster describe`コマンド](https://github.com/jhipster/generator-jhipster/pull/34864)は、コマンド、オプション、プロンプト、および設定オーナーのクエリ可能なカタログを提供します。
* 新しい[`--export-application`オプション](https://github.com/jhipster/generator-jhipster/pull/34913)は、生成されたファイルをディスクに書き込む代わりにzipアーカイブにパックします。
* ブループリントの作成者は、[semver保証付きの文書化された公開API](https://github.com/jhipster/generator-jhipster/pull/34989)を利用できるようになりました。
* [String IDを持つAngularエンティティ](https://github.com/jhipster/generator-jhipster/pull/34869)、[データベースのないOAuth2ゲートウェイでのビルドエラー](https://github.com/jhipster/generator-jhipster/pull/34866)、[すべてのユーザーレコードを削除するテスト](https://github.com/jhipster/generator-jhipster/pull/34867)、[MapStruct式フィールドの増分Liquibaseチェンジログ](https://github.com/jhipster/generator-jhipster/pull/34984)など、多くの古い問題が修正されました。
* ビルドツールを[Node.js 24.21.0](https://github.com/jhipster/generator-jhipster/pull/34876)、[Cypress 16](https://github.com/jhipster/generator-jhipster/pull/34823)、[Vitest 5](https://github.com/jhipster/generator-jhipster/pull/34852)にアップグレードしました。

## インストール方法

NPMを使用してJHipster v9.4.0をインストールするには：

```
npm install -g generator-jhipster@9.4.0
```

JHipster Dockerイメージを使用しても利用可能です。これはソースコードから自動的にビルドされます。

- [Docker Hub](https://hub.docker.com/r/jhipster/jhipster)
- [JHipster Online](https://start.jhipster.tech)

## アップグレード方法

### 自動アップグレード

自動アップグレードには、既存のアプリケーションで[JHipsterアップグレードサブジェネレーター](/upgrading-an-application/)を使用します：

JHipsterのバージョンをアップグレードします：

```
npm update -g generator-jhipster
```

そして、アップグレードサブジェネレーターを実行します：

```
jhipster upgrade
```

より高度なアップグレード機能には、[migrateブループリント](https://github.com/jhipster/generator-jhipster-migrate)も使用できます。

```
npm i -g generator-jhipster-migrate
jhipster-migrate
```

### 手動アップグレード

手動アップグレードの場合、まずJHipsterのバージョンを以下でアップグレードします：

```
npm update -g generator-jhipster
```

既存のプロジェクトがある場合、それは生成されたJHipsterのバージョンを使い続けます。
プロジェクトをアップグレードするには、まず`node_modules`フォルダを削除し、その後以下を実行する必要があります：

```
jhipster
```

また、以下を実行することで、プロジェクトとそのすべてのエンティティを更新できます：

```
jhipster --with-entities
```

エンティティサブジェネレーターを再度実行することで、エンティティを1つずつ更新することもできます。例えば、エンティティ名が_Foo_の場合：

```
jhipster entity Foo --single-entity
```
